# Main v2.17 Codex Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Import upstream `main` at `5d7d80d` into `codex` while preserving the `$icodex` command model, Codex storage paths, same-model review, and independent `$icodex-review` handoff.

**Architecture:** Build the adapted tree on a temporary port branch rooted at `main`, with small verified commits, then merge that branch into `integrate/main-v2.17-codex`. Runtime state and migration behavior live in one Python helper, Codex MCP registration uses dedicated shell entry points, and Markdown skill files consume those stable contracts.

**Tech Stack:** Git, Markdown Codex skills, Python 3 standard library, Bash, Codex CLI `codex mcp`, pytest/unittest-compatible Python tests.

## Global Constraints

- Skill name remains `icodex`; primary invocation is `$icodex <command>`.
- `$icodex start` remains a single-stage alias for `$icodex plan`; `$icodex run` performs staged steps 1 through 6.
- New project artifacts write only to `.ai/icode/`; new global data writes only to `~/.codex/icode_data/`.
- `.icode_output/` and `~/.claude/icode_data/` are read-only legacy sources.
- Active Codex paths never write `~/.claude.json` or execute legacy Claude installers.
- `agents/openai.yaml`, `references/domain-checklists.md`, full mode, staged mode, and `$icodex-review` separation remain intact.
- Existing upstream MCP business logic is not rewritten unless Codex registration requires an adapter.
- No external MCP is installed during development or tests; tests inject a fake Codex CLI.
- The final integration branch must contain both `codex` and `main` histories.

### Task 2: Implement metadata, locking, merged-view, and migration runtime

**Files:**
- Create: `tools/icode_state.py`
- Modify: `tests/test_icode_state.py`
- Create: `tests/test_icode_migration.py`

**Interfaces:**
- Consumes: metadata fixtures from Task 1.
- Produces:
  - `validate_metadata(metadata: dict, run_dir: Path) -> list[str]`
  - `publish_artifact(run_dir: Path, key: str, source: Path, relative_name: str) -> Path`
  - `reserve_patch_number(run_dir: Path) -> int`
  - `load_merged_index(codex_root: Path, claude_root: Path) -> dict`
  - `iter_merged_files(kind: str, codex_root: Path, claude_root: Path) -> list[MergedFile]`
  - `merged_source_digest(codex_root: Path, claude_root: Path) -> str`
  - `migrate_legacy_run(project_root: Path, legacy_run: Path, codex_root: Path) -> Path`
  - `PortableFileLock(path: Path, timeout_seconds: float = 10.0)`
  - CLI subcommands `validate`, `publish-artifact`, `reserve-patch`, `merged-index`, `merged-files`, and `migrate-legacy`.

- [ ] **Step 1: Implement metadata constants and validation**

Define exact constants:

```python
ARTIFACT_KEYS = (
    "requirement", "root_cause", "plan", "plan_review", "final_plan",
    "implementation", "deepcheck", "audit", "patches",
    "delivery_report", "delivery_brief",
)
FULL_PHASES = ("diagnose", "plan", "implement", "self_review", "audit", "verify")
STAGED_STEPS = ("1", "2", "3", "4", "5", "6")
```

`validate_metadata` must enforce ordered prefixes, status/current-phase consistency, required artifact keys by state, existing mapped files, and `patch_count`/delivery-report conditional requirements.

Expose validation through:

```bash
python3 tools/icode_state.py validate --run-dir .ai/icode/<run-name>
```

The command prints JSON `{"ok": true, "errors": []}` on success and exits 1 with populated errors on failure.

- [ ] **Step 2: Implement atomic JSON and artifact publication**

Use same-directory temporary files, `flush()`, `os.fsync()`, `os.replace()`, and validation before replacement. `publish_artifact` must leave the mapping null when metadata replacement fails and may reuse an existing target only after verifying it is a regular file inside `run_dir`.

CLI form:

```bash
python3 tools/icode_state.py publish-artifact --run-dir .ai/icode/<run-name> --key plan --source /tmp/PLAN.md --name PLAN.md
```

- [ ] **Step 3: Implement the portable lock helper**

Use `fcntl.flock` on POSIX and `msvcrt.locking` on Windows. Write PID, hostname, and acquisition time into the lock file; time out after 10 seconds without breaking the lock. Provide context-manager methods `__enter__` and `__exit__`.

`reserve_patch_number` acquires `.ico.lock`, reloads metadata, increments `patch_count`, appends a `patch_history` entry with `status="in_progress"`, atomically writes metadata, and returns the unique number. Its CLI prints only that integer on stdout.

- [ ] **Step 4: Implement the Codex/Claude merged index view**

Parse both `index.json` files. Use Codex entries first, expose same-ID/different-source Claude entries as `legacy:{ticket_id}:{migration_id[:8]}`, and merge `legacy_overlay=true` mutable fields without treating the ticket as migrated. Writes use `.index.lock` and atomic replacement.

`iter_merged_files` accepts only `project_docs`, `module_docs`, or `limits`, returns records with `key`, `path`, and `source` (`codex` or `claude`), and applies Codex precedence per key. `merged_source_digest` hashes both index files and every returned file path/content pair for cache invalidation.

- [ ] **Step 5: Implement recoverable legacy migration**

Validate that `legacy_run.resolve()` is below `<legacy_project>/.icode_output`, reject symlinks/special files, compute `migration_id` and a SHA-256 source manifest, copy to `.migrate-*`, publish to deterministic `.ai/icode/legacy-*`, atomically update the Codex index, and transition `migration_state` from `prepared` to `completed`. A prepared target resumes at index publication; a changed source manifest fails without overwriting either side.

CLI form:

```bash
python3 tools/icode_state.py migrate-legacy --project-root /absolute/project --legacy-run /absolute/project/.icode_output/.icode_output_3 --codex-root /absolute/codex-data
```

- [ ] **Step 6: Add migration and concurrency tests**

Tests must cover successful migration, idempotent retry, same ticket ID from different sources, path escape, source manifest change, simulated index-write failure after directory publication, two concurrent index updates, two concurrent patch reservations, and lock timeout.

Run:


Expected: all tests pass with no writes outside each test temporary directory.
